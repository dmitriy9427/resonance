# 06. Свечение и производительность

## Постобработка

После того как сцена нарисована, кадр проходит через эффекты
(`@react-three/postprocessing`, `Stage.tsx`):

| Эффект | Что делает |
| --- | --- |
| Bloom | ореол вокруг ярких пикселей — неоновое свечение |
| ChromaticAberration | расслоение каналов RGB, усиливается на долях |
| Vignette | затемнение краёв |
| Noise | лёгкое киношное зерно |

Bloom срабатывает только для пикселей ярче порога (`luminanceThreshold`).
Поэтому шейдеры сцен специально отдают цвета ярче 1.0 там, где должно
светиться (края сферы, линии сетки), и тусклые — для «тела».

Параметры эффекта меняются в `useFrame` напрямую через ref на эффект —
без перерисовки React.

## Как держать 60 fps

- **Вся тяжёлая математика — на видеокарте**: позиции 60 000 звёзд и высоты
  рельефа считает шейдер; процессор передаёт только несколько чисел и
  64 значения спектра.
- **Объекты создаются один раз** (`useMemo`), в кадре только меняются.
- **PerformanceMonitor** (drei) следит за частотой кадров: если устройство
  не тянет, плотность пикселей снижается до 1 (на ретина-экранах это в 4
  раза меньше пикселей).
- `antialias: false` — сглаживание краёв не нужно под Bloom и зерном.
- **Своя граница отсечения**: у звёзд, которые двигает шейдер, three.js не
  знает реальных координат — `boundingSphere` задан вручную, иначе галактика
  могла бы пропадать на краю кадра.
- В «Горизонте» строки истории добавляются с фиксированной частотой (45 в
  секунду), а не каждый кадр, — рельеф едет одинаково при любом fps.

## «Меньше движения»

При `prefers-reduced-motion` расслоение цвета выключено, анимации интерфейса
сокращены.

## Ошибки

> **Постобработка с полной плотностью пикселей на ретине.** Bloom на 4K — слайд-шоу. Снижайте DPR,
> когда FPS падает (`PerformanceMonitor`).
>
> **Сглаживание (MSAA) вместе с постобработкой.** Двойная работа. Здесь `multisampling={0}`.
>
> **Вспышки на каждой доле при «меньше движения».** Расслоение цвета на долях выключается.
