# 03. Демо-трек из кода

В проекте нет ни одного звукового файла: демо-трек собирается из
осцилляторов и шума прямо во время игры. Это и демонстрация Web Audio, и
способ обойтись без лицензий на музыку.

## Музыка как данные (`song.ts`)

- Темп 118 BPM, шаг — шестнадцатая доля (16 шагов в такте).
- Аккорды ля минора по два такта: **Am – F – C – G** — одна из самых
  популярных последовательностей в поп-музыке.
- Части: вступление (4 такта) → дроп (12) → брейк (4) → второй дроп (12),
  дальше по кругу.
- `eventsAt(step)` отвечает: что звучит на этом шаге. Например, бочка — на
  шагах 0, 4, 8, 12 («четыре на пол»), бас — на 2, 6, 10, 14 (между ударами,
  отсюда «качающий» транс-бас).

Ноты — в формате MIDI: 69 — ля первой октавы (440 Гц), +12 — октава выше
(частота ×2). `midiToHz(m) = 440 · 2^((m − 69) / 12)`.

Музыка отделена от звука, поэтому её проверяют тесты: «в дропе ровно 4
бочки на такт», «арпеджио играет только ноты аккорда» (`song.test.ts`).

## Инструменты (`synth.ts`)

| Инструмент | Из чего |
| --- | --- |
| Бочка | синус, частота падает 150 → 42 Гц за 0,12 с |
| Клэп | шум через полосовой фильтр, три быстрых «хлопка» |
| Хэт | шум через фильтр высоких частот, 45 мс |
| Бас | пила + суб-синус, фильтр «закрывается» после удара |
| Пэд | три слегка расстроенные пилы на ноту — «широкий» звук |
| Арпеджио | треугольник + синус октавой выше, в эхо |

**Огибающая** — как громкость меняется во времени: быстрая атака, затухание.
Делается автоматизацией параметров:

```ts
gain.gain.setValueAtTime(1, t)
gain.gain.exponentialRampToValueAtTime(0.001, t + 0.4)
```

**Sidechain** — приём электронной музыки: на каждый удар бочки пэд
приглушается и за четверть секунды возвращается. Отсюда характерное
«дыхание». В коде — автоматизация громкости шины пэда в `kick()`.

Эхо — `DelayNode` с обратной связью через фильтр, реверберация —
`ConvolverNode` с импульсом из затухающего шума.

## Точный ритм: «два часа»

Таймеры JS (`setInterval`) неточны: если вкладка занята отрисовкой 3D,
коллбэк опоздает на 10–30 мс — ритм «поплывёт». Часы звуковой карты
(`ctx.currentTime`) точны.

Решение (статья «A Tale of Two Clocks», Chris Wilson):

1. Таймер JS тикает каждые 25 мс.
2. На каждом тике ставим в очередь все ноты, которые должны прозвучать в
   ближайшие 120 мс, **с точным временем по часам звуковой карты**:
   `osc.start(t)`.
3. Даже если тик опоздал, ноты уже стоят в очереди и прозвучат вовремя.
