# 02. Звук в браузере

## Web Audio API за пять минут

Звук в браузере — это **граф узлов**. Каждый узел что-то делает со
звуком и передаёт дальше:

```ts
const ctx = new AudioContext()
const osc = ctx.createOscillator()   // источник: генератор волны
const gain = ctx.createGain()        // обработка: громкость
osc.connect(gain).connect(ctx.destination) // выход: динамики
osc.start()
```

Граф «Резонанса» (`src/audio/engine.ts`):

```
синтезатор ─┐
<audio> ────┼─► input ─► analyser ─► volume ─► динамики
микрофон ───┘ (только в analyser — иначе звук из колонок попадёт в микрофон и завоет)
```

Важное ограничение: браузер **не даёт включить звук без действия
пользователя**. Поэтому `AudioContext` создаётся лениво — при первом клике
на «Демо-трек», «Свой файл» или «Микрофон».

## Что такое спектр

Звук — это колебание воздуха, записанное как форма волны (сотни значений в
миллисекунду). Любую волну можно разложить на сумму синусоид разной частоты —
это **преобразование Фурье** (FFT — быстрый алгоритм для него).

`AnalyserNode` делает FFT за нас:

```ts
analyser.fftSize = 2048
const freq = new Uint8Array(analyser.frequencyBinCount) // 1024 ячейки
analyser.getByteFrequencyData(freq) // громкость каждой частоты, 0…255
```

1024 ячейки равномерно покрывают диапазон от 0 до половины частоты
дискретизации (при 48 000 Гц — до 24 000 Гц), то есть каждая — ~23 Гц.
Номер ячейки для частоты — `binOf()` в `analysis.ts`.

## Полосы частот

Графике удобнее три числа, чем тысяча:

| Полоса | Частоты | Что там звучит |
| --- | --- | --- |
| bass | 20–150 Гц | бочка, бас |
| mid | 150–2000 Гц | голос, гитары, клавиши |
| treble | 2–12 кГц | тарелки, хэты, «воздух» |

`bandLevel()` — среднее по ячейкам полосы.

## Почему спектр логарифмический

Слух логарифмический: переход 50 → 100 Гц и 5000 → 10 000 Гц звучит как
одинаковый шаг (октава). В линейном спектре все басы уместились бы в 5–6
ячеек из 1024, а на верха ушло бы 90 % экрана. `logBands()` нарезает
спектр на 64 полосы так, что каждая следующая шире предыдущей в одно и то же
число раз — басы получают много полос, как и на слух.

## Сглаживание: быстро вверх, медленно вниз

Сырые значения прыгают каждый кадр — картинка дрожала бы. `follow()`:

```ts
prev + (next - prev) * (next > prev ? attack : release)
```

Подъём быстрый (удар виден сразу), спад медленный (картинка плавно
«остывает»). Так работают стрелочные индикаторы на пультах. Коэффициенты
умножаются на длительность кадра, чтобы при 60 и 120 fps скорость была
одинаковой.

## Детектор долей

Доля — удар, на который хочется «вздрогнуть». Алгоритм `BeatDetector`:

1. Храним энергию баса за последнюю секунду (~60 кадров).
2. Доля = энергия сейчас **в 1,35 раза выше среднего** за секунду **и**
   прямо сейчас растёт **и** с прошлой доли прошло ≥ 240 мс.

Сравнение со средним, а не с фиксированным порогом, делает детектор
независимым от громкости трека. Условие «растёт» добавлено после теста: без
него резкий переход тишина → громко давал серию ложных долей, пока среднее
«догоняло» (см. `analysis.test.ts`).

На доле `levels.pulse` становится 1 и затухает за ~0,3 с — сцены используют
его для толчков и вспышек.

## Файл и микрофон

- **Файл** играет через `<audio>` + `createMediaElementSource`: так бесплатно
  работают перемотка и длительность. Узел можно создать для элемента только
  один раз, поэтому `<audio>` один, меняется только `src`
  (`URL.createObjectURL(file)`).
- **Микрофон** — `getUserMedia`. Подавление эха и шума выключено: оно
  «съедает» музыку, принимая её за помеху.

## Ошибки

> **`new AudioContext()` при загрузке страницы.** Браузер запрещает звук без действия
> пользователя — контекст будет «приостановлен». Создавайте и `resume()` по клику.
>
> **Микрофон в динамики.** Звук из колонок снова попадает в микрофон — свист. Микрофон — только в
> анализатор.
>
> **Второй `createMediaElementSource` для того же `<audio>`.** Ошибка: источник для элемента
> создаётся один раз. Один `<audio>`, меняется только `src`.
>
> **Порог доли — числом.** На тихом треке долей нет, на громком — каждая нота. Сравнивайте со
> **средним** за последнюю секунду.
>
> **Сглаживание без учёта FPS.** На мониторе 120 Гц всё реагирует вдвое резче. Коэффициент
> умножают на длительность кадра.

## Попробуйте сами

1. Частота дискретизации 48 000 Гц, `fftSize = 2048`. Сколько полос в спектре и какой ширины?
2. Почему басы в линейном спектре «занимают пару ячеек»?
3. Поставьте `release` у баса равным `attack`. Как изменится картинка?

<details>
<summary>Ответы</summary>

1. `frequencyBinCount = 1024` полосы от 0 до 24 000 Гц — по ~23,4 Гц каждая.
2. Бас 20–150 Гц — это 130 Гц из 24 000: примерно 6 полос из 1024. А слух воспринимает октаву
   50–100 Гц такой же «широкой», как 5–10 кГц, — отсюда логарифмические полосы.
3. Сфера будет падать так же резко, как подпрыгивает: картинка задёргается в такт каждой ноте.
</details>
