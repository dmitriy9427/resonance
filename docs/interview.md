# Шпаргалка к собеседованию

**Как получить спектр звука в браузере?**
Web Audio: источник → `AnalyserNode` → `getByteFrequencyData`. Внутри FFT,
1024 ячейки от 0 до половины частоты дискретизации. Дальше — полосы и
логарифмическая нарезка, потому что слух логарифмический.

**Как определяются доли?**
Энергия баса сравнивается со средним за секунду (×1,35), плюс энергия должна
расти и между долями ≥ 240 мс. Относительный порог — независимость от
громкости трека.

**Почему уровни звука не в React-состоянии?**
Они меняются 60 раз в секунду. Через state React перерисовывал бы
интерфейс каждый кадр. Изменяемый объект `levels` читается в `useFrame` и
передаётся прямо в uniform'ы. В Zustand — только редкое: пауза, сцена,
громкость.

**Что такое useFrame и его приоритет?**
Колбэк перед каждым кадром. Приоритет задаёт порядок: «насос» данных с −1
выполняется раньше сцен. Приоритет > 0 отключает автоматическую отрисовку
R3F — так работает постобработка.

**Почему 60 000 частиц не тормозят?**
Позиции считает вершинный шейдер на GPU; процессор передаёт время и 64
числа спектра. Геометрия создана один раз.

**Как сделан демо-трек без файлов?**
Осцилляторы и шум Web Audio, огибающие через автоматизацию параметров.
Ноты — данные в `song.ts`, синтезатор только озвучивает. Ритм — схема «двух
часов»: `setInterval` планирует ноты на 120 мс вперёд по точным часам
`AudioContext`.

**Какие были проблемы?**
- Мини-спектр падал на телефоне: скрытый canvas имел ширину 0, радиус
  скругления выходил отрицательным — теперь размер проверяется каждый кадр.
- Солнце мигало на каждом ударе — дано своё медленное сглаживание.
- Детектор долей давал серию ложных срабатываний на резком переходе к
  громкому звуку — добавлено условие «энергия растёт» (нашёл тест).
- Float-текстура с линейной фильтрацией не везде поддерживается —
  история спектра хранится в байтах.

**Что бы улучшил?**
Запись видео сцены (`canvas.captureStream` + MediaRecorder), сцены на WebGPU
(TSL), синхронизация смены сцен с частями трека, настройки чувствительности.
